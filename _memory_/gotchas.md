## Chantier 5, verbe `console` (29/08)

- **L'API Search Console exige un projet de quota avec un jeton gcloud.** Sans en-tête `x-goog-user-project`, `sites.list` répond 403 `SERVICE_DISABLED` même avec le bon scope. Il faut poser `GSC_QUOTA_PROJECT` et activer l'API sur ce projet (`gcloud services enable searchconsole.googleapis.com --project=<projet>`). Un compte de service n'en a pas besoin. Re-vérifiable : `curl -H "Authorization: Bearer $(gcloud auth application-default print-access-token)" https://www.googleapis.com/webmasters/v3/sites` sans en-tête rend le 403.
- **Le 403 `SERVICE_DISABLED` ne vient jamais d'une variable absente.** Si `GSC_QUOTA_PROJECT` manque, le code s'arrête avant tout appel réseau. La seule branche réelle est une variable posée sur un projet sans l'API activée, et Google nomme alors le projet fautif dans son message. Un message d'erreur qui dit « variable absente » dans ce cas envoie sur une fausse piste : trouvé par la revue finale, corrigé.
- **Search Console a deux sortes de propriété** et l'API exige le nom exact : `sc-domain:exemple.fr` ou `https://exemple.fr/`. Ne jamais fabriquer un `siteUrl` depuis un hôte : le résoudre dans ce que `sites.list` a rendu, sinon 403 ou 404 silencieux sur la moitié des cas. `siteEntry` **n'a pas d'ordre garanti** : deux appels successifs le même jour ont rendu un ordre différent.
- **Bing sérialise ses dates au format .NET `/Date(<ms>[±hhmm])/`.** Une URL inconnue de `GetUrlInfo` ne rend **pas** `null` mais un objet complet dont les dates valent `DateTime.MinValue`, soit `-62135568000000` ms. Sans décodage, l'utilisateur lit `/Date(-62135568000000-0800)/` à l'écran. Le décalage horaire du suffixe s'ignore sans risque : les millisecondes sont un epoch UTC et Bing ne sert que des décalages négatifs. Comparer la sentinelle avec `<=` et non `===`, sinon l'heure d'été (`-0700`) la rate.
- **`HttpStatus` de Bing vaut `0` même sur une URL connue et indexée.** Ce n'est pas un discriminant et l'afficher induit en erreur ; le seul signal fiable de « inconnue » est la sentinelle de `DiscoveryDate`.
- **`ErrorCode: 0` de Bing vaut `None` dans l'enum officielle : c'est un succès.** Ne lever que sur les codes non nuls, sinon un succès devient « Bing a refusé : None ».
- **Un `catch` qui rend une liste vide fait mentir la sortie.** Un 403 sur les sitemaps d'une propriété s'affichait « aucun sitemap déclaré ». Distinguer « non lisible » (`null`) de « vide » (`[]`) partout où une lecture peut échouer.
- **`bun install` est nécessaire dans un worktree neuf** : `node_modules` est ignoré par git, donc absent, et la suite échoue sur `Cannot find package 'robots-parser'` avant d'avoir rien prouvé.
- **Le dossier `.superpowers/sdd/` est ignoré par git** : le registre d'exécution et tous les rapports de revue meurent avec le worktree. Copier le registre dans `docs/superpowers/journaux/` avant de supprimer le worktree.
- **Un brief de tâche généré d'avance devient périmé** dès qu'on corrige le plan. Régénérer juste avant chaque dispatch (arrivé le 29/08 : l'implémenteur de la tâche 6 a travaillé sur une clé de test corrigée entre-temps, rattrapé par sa vigilance seule).
- `env -u VAR PATH=/usr/bin bun …` **ne s'exécute pas** : `env` résout la commande avec le `PATH` qu'il vient de poser, et `bun` n'y est pas. Pour retirer `gcloud` du `PATH` sans perdre `bun` : `PATH="$(dirname "$(command -v bun)")"`, les deux vivant dans des dossiers différents.
